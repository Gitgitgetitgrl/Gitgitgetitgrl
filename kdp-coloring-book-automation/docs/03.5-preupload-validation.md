# 03.5 — Pre-Upload CSV Validation (Part 3.5)

Validate metadata CSV before it enters the upload workflow. Implemented in
[`../validation/validate_csv.py`](../validation/validate_csv.py), driven by the centralized
rules file [`../validation/rules.yaml`](../validation/rules.yaml) (no KDP rule is hard-coded
in logic).

## 4-layer validation

1. **File-level** — encoding, delimiter, header row, duplicate columns, required columns present.
2. **Field-level** — data type and format checks per column.
3. **KDP metadata rules** — title/subtitle length, keyword count (7, unique), category count
   (2), valid trim/bleed/paper enums, page-count bounds.
4. **Final gate** — `approval_status` must be `Approved` and `version` present (+ optional
   file-existence check). Only rows passing this may enter META_APPROVED.

## Required fields checklist

- [ ] `task_id` present
- [ ] `book_slug` present, unique
- [ ] `title` within KDP character limit
- [ ] `subtitle` within KDP character limit
- [ ] 7 keywords present, none duplicated
- [ ] 2 categories selected
- [ ] `trim_size` one of: 8.5x11, 8.5x8.5, 6x9, 8x10, 8.25x8.25
- [ ] `bleed` set (bleed / no_bleed)
- [ ] `cover_file` and `interior_file` paths resolve (with `--check-files`)
- [ ] `approval_status` = Approved (final gate)
- [ ] `version` is an integer, incremented from the prior row

## Usage

```bash
# draft check (layers 1-3)
python validation/validate_csv.py templates/META_DRAFT.csv

# pre-approval check (all 4 layers)
python validation/validate_csv.py templates/META_APPROVED.csv --final-gate

# also verify referenced files exist, relative to an assets root
python validation/validate_csv.py templates/META_APPROVED.csv --final-gate \
    --check-files --assets-root ./assets
```

Exit code `0` = valid, `1` = errors found, `2` = file unreadable — so it drops straight into
a CI or pre-upload gate. Run the unit tests with `pytest validation/test_validate.py`.

## Changing the rules

Edit `validation/rules.yaml` (character limits, valid enums, page-count bounds, final-gate
behavior). The validator and the tests read from it, so one edit updates everything.
